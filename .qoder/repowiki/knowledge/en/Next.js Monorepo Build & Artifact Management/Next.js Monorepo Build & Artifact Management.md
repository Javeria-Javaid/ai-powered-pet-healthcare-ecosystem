## What system/approach is used

This project is a single-package Next.js (App Router) application built and shipped via the **Next.js CLI** (`next build`, `next dev`, `next start`). There are no Makefiles, Dockerfiles, CI pipelines, or separate monorepo tooling — the entire build surface lives in `package.json` scripts plus a handful of configuration files at the repository root. Prisma is used for database schema management and seeding, invoked through its own CLI configured via `prisma.config.ts`. Linting is handled by ESLint v9 with the Next.js recommended config; styling uses Tailwind CSS v4 via PostCSS.

## Key files and packages

- `package.json` — defines all npm scripts (`dev`, `build`, `start`, `lint`) and pins runtime dependencies (`next 16.3.2`, `react 19.2.8`, `@prisma/client 7.9.1`, `argon2`, `pg`, etc.) and dev dependencies (`eslint 9`, `tailwindcss 4`, `prisma 7.9.1`, `typescript 5`).
- `next.config.ts` — empty Next.js config object; no custom bundling, output, or environment overrides.
- `tsconfig.json` — TypeScript compiler options: `target: ES2017`, `strict: true`, `noEmit: true`, `moduleResolution: bundler`, JSX `react-jsx`, path alias `@/* → ./*`, includes `.next/types` generated by Next.
- `prisma.config.ts` — Prisma configuration pointing to `prisma/schema.prisma`, migrations under `prisma/migrations`, seed script `node ./prisma/seed.js`, and datasource URL from `process.env.DATABASE_URL`.
- `postcss.config.mjs` — registers `@tailwindcss/postcss` as the only PostCSS plugin.
- `eslint.config.mjs` — extends `eslint-config-next/core-web-vitals` and `eslint-config-next/typescript`; explicitly ignores `.next/**`, `out/**`, `build/**`, `next-env.d.ts`.
- `prisma/schema.prisma` + `prisma/migrations/` — Prisma data model and migration history (PostgreSQL via `@prisma/adapter-pg`).
- `.env` / `.env.example` — environment variables consumed at build/runtime (e.g., `DATABASE_URL`).

## Architecture and conventions

- **Single-package layout**: All source code, configs, and scripts live in one directory tree. There is no workspace/monorepo manager (no `pnpm workspaces`, `turbo`, `nx`, etc.).
- **Build pipeline is flat**: The standard Next.js lifecycle is used unchanged — development via `npm run dev`, production build via `npm run build` (which emits into `.next/`), and production serve via `npm run start`.
- **TypeScript is transpiled but not emitted**: `noEmit: true` means TypeScript acts purely as a type-checker; the actual JS bundles are produced by Next.js's internal bundler.
- **Path aliases**: `@/*` maps to the repo root, used throughout `app/` and `lib/` imports.
- **Prisma-first data layer**: Database schema is the single source of truth; migrations live under `prisma/migrations/` and the seed command is wired into Prisma's config so it runs automatically with `prisma migrate deploy --seed`.
- **Linting is Next.js opinionated**: ESLint pulls in Next.js best practices and Core Web Vitals rules; there are no custom rule overrides beyond adjusting ignore patterns.
- **Styling pipeline**: Tailwind CSS v4 is processed through PostCSS using the official `@tailwindcss/postcss` plugin; no additional PostCSS plugins are registered.

## Conventions and constraints

- **Dependency pinning**: Runtime versions are pinned in `package.json` (e.g., `next: 16.3.2`, `react: 19.2.8`, `@prisma/client: ^7.9.1`); lockfile (`package-lock.json`) is committed.
- **Environment-driven config**: Prisma datasource URL comes exclusively from `process.env.DATABASE_URL` (loaded via `dotenv/config` in `prisma.config.ts`); no hardcoded connection strings.
- **No custom build hooks**: `next.config.ts` is an empty config object — all customization goes through Next.js defaults and environment variables.
- **Generated artifacts are ignored**: `.next/` is listed in ESLint ignores and is the standard Next.js build output directory; nothing else is treated as a build artifact.
- **No containerization or CI**: No `Dockerfile`, `docker-compose.yml`, GitHub Actions workflows, Makefiles, or shell build scripts were found in the repository. Deployment guidance in `README.md` points to Vercel and the Next.js deployment docs.
- **Prisma seed is part of migrations**: The seed script path is declared in `prisma.config.ts`, making seeding part of the migration workflow rather than a separate npm script.
