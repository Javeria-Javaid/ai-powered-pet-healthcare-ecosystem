Single-file Prisma schema (`schema.prisma`) declares a PostgreSQL datasource with `prisma-client-js` generation. The model centers on a `User` entity (with `UserRole` enum: PET_OWNER, VETERINARIAN, CLINIC_ADMIN, PLATFORM_ADMIN) that branches into domain entities: `Pet`, `Veterinarian`, `Clinic`, a many-to-many `VetClinicAssociation` bridge with `AssociationStatus`, versioned `MedicalRecord`/`MedicalRecordVersion`, plus supporting models for `Appointment`, `Prescription`, `Vaccination`, `Medication`, `Allergy`, `HealthCondition`, `HealthMetric`, `Document`, `Notification`, `Reminder`, `AIConversation`/`AIMessage`, `AuditLog`, `Session`, `Conversation`, and `Message`. Relationships use explicit named relations (e.g. `VetUser`, `Verifier`, `AuditUser`, `ClinicAdmins`, `OwnerConversations`, `SentMessages`, `VetConversations`) and enforce referential integrity via `onDelete` rules — typically `Cascade` for child records and `SetNull` for optional cross-references like clinic admins or conversation participants. Migration history is stored under `migrations/` as timestamped folders managed by Prisma Migrate, with `migration_lock.toml` pinning provider state. `seed.js` bootstraps sample data using `@prisma/client` with a custom `PrismaPg` adapter over `pg.Pool`; it resolves Prisma Cloud's `prisma+postgres://` connection strings by decoding the base64 `api_key` query param to extract the underlying `databaseUrl`, hashes passwords with argon2, and uses deterministic placeholder UUIDs combined with `upsert` calls keyed by stable IDs to ensure idempotent seeding across repeated runs.
