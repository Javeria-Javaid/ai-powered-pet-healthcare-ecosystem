The module is centered on a single `schema.prisma` file declaring a PostgreSQL datasource with `prisma-client-js` generation. The domain model is anchored by a `User` entity (with `UserRole` enum: PET_OWNER, VETERINARIAN, CLINIC_ADMIN, PLATFORM_ADMIN) that branches into role-specific profiles (`Veterinarian`, optional `Clinic` admin link), and owns child entities such as `Pet`, `Appointment`, `Notification`, `Reminder`, `Document`, `Session`, and `AuditLog`. Medical history is versioned through `MedicalRecord` + `MedicalRecordVersion` with an `isCurrent` flag, while vet-clinic membership uses a many-to-many bridge `VetClinicAssociation` with `AssociationStatus`. Messaging is split into two trees: AI-driven `AIConversation`/`AIMessage` per user, and owner-vet `Conversation`/`Message` linked optionally to an `Appointment`. Relationships are explicit with named relations (e.g. `VetUser`, `Verifier`, `AuditUser`, `OwnerConversations`, `SentMessages`, `VetConversations`) and enforce referential integrity via `onDelete` rules — `Cascade` for owned children and `SetNull` for optional cross-references like conversation participants or clinic admins. Query performance is supported by `@@index` pragmas on frequently filtered columns. Migration history lives under `migrations/` as timestamped folders managed by Prisma Migrate, pinned by `migration_lock.toml`. `seed.js` is a standalone Node script that constructs a `PrismaClient` over `@prisma/adapter-pg` with a raw `pg.Pool`, decodes Prisma Cloud's `prisma+postgres://` connection strings by base64-decoding the `api_key` query param to obtain the underlying `databaseUrl`, hashes passwords with argon2, and uses deterministic placeholder UUIDs plus `upsert` calls keyed by stable IDs to guarantee idempotent re-runs.
