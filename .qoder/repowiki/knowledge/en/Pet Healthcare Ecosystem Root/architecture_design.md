The root orchestrates four child modules through standard Next.js conventions: `app_frontend` (Next.js App Router pages + `/api` route handlers) imports from `lib_shared` to perform Prisma queries, manage Argon2-hashed sessions via cookies, and invoke multi-provider AI assistants; `database_schema` under `prisma/` defines the PostgreSQL model consumed at runtime by `lib_shared`; `docs` holds product/architecture specs. Cross-child wiring is centralized in root-level config files: `proxy.ts` enforces route-level authentication on protected path prefixes (`/dashboard`, `/appointments`, `/pets`, `/medical-records`, `/vet`) by checking the `session_token` cookie before any page or API handler runs; `prisma.config.ts` points Prisma to `prisma/schema.prisma` and runs `prisma/seed.js` during migrations; `tsconfig.json` and `eslint.config.mjs` provide shared TypeScript paths (`@/*` alias) and linting rules consumed uniformly by both the frontend and shared library.
