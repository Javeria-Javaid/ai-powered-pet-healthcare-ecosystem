The module is organized as three sibling entry points plus an `ai/` sub-package with a one-way dependency direction: `ai.ts` depends on `auth.ts` and `db.ts`; `auth.ts` depends only on `db.ts`; `db.ts` has no intra-module dependencies.

- `db.ts` exports a singleton `PrismaClient` backed by `@prisma/adapter-pg` over a `pg.Pool`. In production it creates a fresh pool per process; in development it reuses `globalThis.prisma` / `globalThis.pool` to survive hot-reloads without socket exhaustion.
- `auth.ts` implements cookie-based sessions via Next.js `next/headers` cookies. Passwords are hashed with `argon2.argon2id`, session tokens are SHA-256 hashed before storage in the `Session` Prisma model, and `requireAuth` / `requireRole` act as server-side middleware helpers that throw string-typed errors (`UNAUTHENTICATED`, `FORBIDDEN`). Sessions use a sliding-window expiry refreshed when less than one hour remains, with a fixed two-hour lifetime.
- `ai.ts` defines the `AIProvider` interface (`generateResponse(messages, tools)`) and a `FallbackProvider` class (OpenRouter-backed), while `getAIProvider()` selects the active provider at runtime based on the `BOOKING_ASSISTANT_PROVIDER` env var, defaulting to Gemini. Tool definitions live in the `AI_TOOLS` array and `executeTool(name, argsStr, userId)` dispatches to Prisma-backed handlers (pet lookup, health timeline, vet search, slot checking, booking creation/cancellation) with ownership verification via the local `verifyPetOwnership` helper. The `ai/providers/` sub-package isolates concrete backends (`gemini.ts`, `qwen.ts`) behind the `AIProvider` interface so new providers can be added without touching core logic.
