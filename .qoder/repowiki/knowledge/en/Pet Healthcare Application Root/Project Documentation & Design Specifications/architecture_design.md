The docs directory is organized as a sequential design pipeline mirroring the documented flow PRODUCT → REQUIREMENTS → ARCHITECTURE → FEATURES → IMPLEMENTATION. The top-level README.md defines folder purposes and core rules, acting as the entry point that enforces this hierarchy. `01-product/` holds the project blueprint (vision, principles, user personas, MVP priorities). `02-requirements/` captures reviewed requirements, open questions, and formal decisions (e.g., ORM, database, scope locks). `03-architecture/` translates decisions into concrete technical specs: system architecture, database schema, API contracts, AI architecture with Qwen context retrieval, Alibaba Cloud service mapping, and security/RBAC definitions. Each subfolder uses numeric prefixes to enforce ordering and versioned evolution of the design artifacts.
