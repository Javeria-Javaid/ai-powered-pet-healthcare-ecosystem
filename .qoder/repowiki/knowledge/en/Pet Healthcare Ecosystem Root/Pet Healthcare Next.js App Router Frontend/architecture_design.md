The module is organized by the Next.js App Router into three cooperating layers under `app/`: (1) `api/**` exposes server-side Route Handlers for auth (`auth/*`), pets, clinics, vet, appointments, conversations, and AI chat endpoints; (2) top-level folders `dashboard`, `clinic/dashboard`, and `vet/dashboard` render role-specific pages via Next.js routing; (3) `components/` holds presentational React sections composed in the root layout and landing page. Cross-cutting concerns — site metadata and HTML shell in `layout.tsx`, global Tailwind theme in `globals.css`, and the public landing page in `page.tsx` — are centralized at the module root so every child route shares the same shell and styling context without importing them individually. The landing page acts as the entry point: it checks `/api/auth/me` on mount and redirects to the appropriate role dashboard (`/vet/dashboard`, `/clinic/dashboard`, or `/dashboard`) based on the user's role, and it also dynamically loads Google Identity Services and calls `/api/auth/google/config` + `/api/auth/google/callback` to complete OAuth login before routing.
